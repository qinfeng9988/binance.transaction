## 新增需求

### 需求:系统必须提供策略基类接口
系统必须定义 BaseStrategy 抽象基类，所有具体策略必须继承此类并实现 on_bar 方法。

#### 场景:实现自定义策略
- **当** 开发者创建新策略类继承 BaseStrategy
- **那么** 必须实现 on_bar(symbol, timeframe, klines, positions) 方法并返回 Signal 列表

#### 场景:策略注册
- **当** 系统启动时加载策略配置
- **那么** 系统根据配置中的策略名称自动注册并实例化对应策略

### 需求:系统必须支持多周期多币种策略运行
系统必须允许同一策略在多个 timeframe（如 5m、1h、4h）和多个交易对上同时运行。

#### 场景:多周期调度
- **当** 策略配置了 timeframes: ["5m", "1h", "4h"]
- **那么** 系统按各自频率独立触发每个周期的 on_bar 调用

#### 场景:多币种调度
- **当** 策略配置了 symbols: ["BTCUSDT", "ETHUSDT"]
- **那么** 系统在相同 timeframe 下对每个币种分别执行策略逻辑

### 需求:系统必须支持策略运行模式切换
系统必须通过配置支持 paper（模拟）、live_confirm（实盘+确认）、live_auto（实盘全自动）三种模式。

#### 场景:paper 模式运行
- **当** 策略 mode=paper
- **那么** 策略产生的信号仅记录到日志和数据库，不执行真实下单

#### 场景:模式切换生效
- **当** strategies.yaml 中的 mode 配置被修改
- **那么** 系统热重载后新信号按新模式处理

### 需求:系统必须支持策略启停控制
系统必须允许通过配置启用或禁用单个策略，不影响其他策略运行。

#### 场景:禁用策略
- **当** 策略配置 enabled=false
- **那么** 系统停止调用该策略的 on_bar 方法但保留已持仓状态

#### 场景:启用策略
- **当** 策略配置从 enabled=false 改为 enabled=true
- **那么** 系统恢复该策略的周期调度
