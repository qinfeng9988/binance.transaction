## 新增需求

### 需求:系统必须记录结构化日志
系统必须使用 Python logging 模块，按模块分级输出日志，包含时间戳、级别、模块名和消息内容。

#### 场景:策略执行日志
- **当** 策略 on_bar 执行
- **那么** 日志记录 [INFO] strategies - BTCUSDT 5m: 产生 BUY 信号, 价格=4500, 止损=4450

#### 场景:风控拒绝日志
- **当** 风控模块拒绝一笔交易
- **那么** 日志记录 [WARNING] risk - BTCUSDT 杠杆超限: 请求 10x, 限制 5x

### 需求:系统必须记录交易信号到文件
系统必须将所有交易信号追加写入日志文件，便于后续分析和回查。

#### 场景:信号日志
- **当** 策略产生信号
- **那么** 信号详细信息（币种、方向、价格、止损、策略名）写入 signals.log 文件

#### 场景:执行结果日志
- **当** 订单执行完成（或 paper 模式模拟执行）
- **那么** 执行结果（成交状态、实际价格、手续费）写入 trades.log 文件

### 需求:系统必须支持日志分级输出
系统必须支持将不同级别的日志输出到不同目标。

#### 场景:终端输出 INFO 及以上
- **当** 系统运行
- **那么** INFO、WARNING、ERROR 级别日志输出到终端

#### 场景:文件记录所有级别
- **当** 系统运行
- **那么** 所有级别日志写入日志文件
