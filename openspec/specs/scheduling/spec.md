## 新增需求

### 需求:系统必须支持多周期定时调度
系统必须能够按配置的时间间隔（如 5m、1h、4h）定时触发策略执行。

#### 场景:5 分钟周期触发
- **当** 系统配置了 5m timeframe
- **那么** 系统每 5 分钟调用一次策略的 on_bar 方法

#### 场景:多周期并行
- **当** 系统同时配置了 5m、1h、4h 三个 timeframe
- **那么** 三个周期独立运行，互不阻塞

### 需求:系统必须在周期触发前获取最新 K 线
系统必须在每次触发策略 on_bar 之前，确保从交易所或本地数据库获取到最新的 K 线数据。

#### 场景:K 线数据不足
- **当** 本地 K 线数据不足策略计算所需的最小条数
- **那么** 系统从 Binance API 拉取补充数据

### 需求:系统必须支持调度启停控制
系统必须能够在运行时启动或停止特定策略的调度。

#### 场景:策略启停
- **当** 策略配置从 enabled=true 变为 enabled=false
- **那么** 系统停止该策略的周期触发但保留调度槽位

### 需求:系统必须记录调度执行情况
系统必须记录每次策略执行的开始时间、结束时间和执行结果。

#### 场景:记录执行耗时
- **当** 策略 on_bar 执行完成
- **那么** 系统记录本次执行的耗时和是否成功
