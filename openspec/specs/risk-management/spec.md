## 新增需求

### 需求:系统必须对每笔交易执行止损检查
系统必须在下单前计算止损价格，确保价格偏离止损位的亏损不超过配置的百分比（默认仓位价值的 1.5%）。

#### 场景:止损位在支撑位下方
- **当** 策略在入场价 4500 做多，支撑位 4480
- **那么** 系统设置止损位在 4450（偏离约 1.1%），并拒绝止损位低于 4430（偏离 1.5%）的下单请求

### 需求:系统必须限制单笔交易的最大亏损
系统必须确保单笔交易的潜在亏损不超过保证金的 15%。

#### 场景:自动降杠杆
- **当** 止损距离 × 当前杠杆 > 15%
- **那么** 系统自动降低杠杆使 止损距离 × 杠杆 ≤ 15%

#### 场景:超过上限拒绝交易
- **当** 即使降至最低杠杆，止损距离 × 杠杆仍 > 15%
- **那么** 系统拒绝此笔交易并记录日志

### 需求:系统必须根据币种类型限制杠杆上限
系统必须对主流币（BTC/ETH/SOL）限制最高 5x 杠杆，对山寨币限制最高 3x 杠杆。

#### 场景:主流币杠杆检查
- **当** BTCUSDT 下单请求杠杆为 10x
- **那么** 系统拒绝并将杠杆降至 5x

#### 场景:山寨币杠杆检查
- **当** PAXUSDT 下单请求杠杆为 5x
- **那么** 系统拒绝并将杠杆降至 3x

### 需求:系统必须执行日累计亏损限制
系统必须追踪当日累计亏损，当达到保证金的 30% 时停止所有新交易。

#### 场景:触发日亏损上限
- **当** 当日累计亏损达到保证金的 30%
- **那么** 系统暂停所有策略的新开仓操作

#### 场景:日亏损重置
- **当** 到达新交易日（UTC 0:00）
- **那么** 系统重置日累计亏损计数器

### 需求:系统必须限制单币种仓位占比
系统必须确保单个币种的名义仓位价值不超过总资金的可配置比例。

#### 场景:单币种仓位超限
- **当** BTC 现有仓位 + 新订单 > 总资金的配置上限
- **那么** 系统拒绝新增仓位或仅允许部分成交

### 需求:系统必须限制最大同时持仓数
系统必须限制同时持有的币种数量，防止资金过度分散。

#### 场景:达到最大持仓数
- **当** 当前持仓数等于配置的最大持仓数
- **那么** 系统拒绝新开仓请求

### 需求:风控参数必须支持冷静期配置
系统必须在 `risk.yaml` 中支持连续亏损冷静期配置，触发后一定时间内拒绝新开仓信号。

#### 场景:连续亏损触发冷静期
- **当** `risk.yaml` 配置 `max_consecutive_losses: 3` 和 `cooldown_duration_seconds: 3600`，且回测或实盘中连续亏损达 3 次
- **那么** 系统在接下来 3600 秒内拒绝所有新开仓信号（反向平仓和加仓不受限）

#### 场景:冷静期配置默认值
- **当** `risk.yaml` 未配置 `max_consecutive_losses` 或 `cooldown_duration_seconds`
- **那么** 系统必须使用默认值（max_consecutive_losses=3, cooldown_duration_seconds=3600），不报错

### 需求:风控参数必须支持总风险上限配置
系统必须在 `risk.yaml` 中支持总风险上限配置，所有持仓的潜在最大亏损占余额比例不得超过此值。

#### 场景:总风险超限拒绝新开仓
- **当** `risk.yaml` 配置 `max_total_risk_pct: 8.0`，且当前所有 open positions 的总风险占比已达 8%
- **那么** 系统必须拒绝下一笔新开仓信号

#### 场景:加仓降级规则
- **当** 连续亏损次数达到 `max_consecutive_losses` 阈值
- **那么** 系统必须将加仓上限降低 1 级（即 max_additions - 1），最低不低于 0

### 需求:RiskManager 必须从配置读取所有参数化指标
系统必须让 `RiskManager` 从 `risk.yaml` 读取冷静期、加仓降级、总风险上限等参数，禁止在引擎代码中硬编码这些值。

#### 场景:风控参数化读取
- **当** 实盘 paper 模式或回测启动
- **那么** `RiskManager` 必须从 `risk.yaml` 加载所有参数，引擎代码（`PaperTradingEngine`、`BacktestKlineDriver`、信号路由函数）不得出现这些魔法数字

#### 场景:回测与实盘共享风控配置
- **当** 用户运行回测和实盘 paper 模式
- **那么** 两者必须读取同一份 `risk.yaml`，确保风控行为一致
