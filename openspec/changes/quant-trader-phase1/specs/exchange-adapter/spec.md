## 新增需求

### 需求:系统必须支持 Binance 交易所接入
系统必须通过 ccxt 库连接 Binance API，支持现货和合约（合约）两种交易类型的行情获取与下单操作。

#### 场景:初始化 Binance 连接
- **当** 系统启动并读取 exchanges.yaml 配置
- **那么** 系统使用配置的 API Key 和 Secret 初始化 ccxt Binance 实例

#### 场景:获取 K 线数据
- **当** 策略引擎请求指定币种的 K 线数据
- **那么** 系统通过 ccxt 调用 fetch_ohlcv 接口返回 OHLCV 数据

#### 场景:获取账户余额
- **当** 系统需要查询账户资产状况
- **那么** 系统返回现货和合约账户的余额信息

#### 场景:适配器接口可扩展
- **当** 需要新增交易所支持时
- **那么** 系统只需实现相同的 ExchangeAdapter 接口并注册即可

### 需求:系统必须支持模拟交易模式 (paper trading)
系统必须在 paper 模式下模拟下单、持仓和结算流程，不调用真实交易 API。

#### 场景:paper 模式下单
- **当** 策略发出买入信号且 mode=paper
- **那么** 系统记录信号但不发送真实订单到交易所

#### 场景:paper 模式持仓模拟
- **当** paper 模式下有模拟持仓
- **那么** 系统根据市场价格更新模拟持仓的盈亏

### 需求:系统必须支持实盘人工确认模式
系统必须在 live_confirm 模式下发送交易信号到通知通道，等待人工确认后执行下单。

#### 场景:发送确认通知
- **当** 策略发出信号且 mode=live_confirm
- **那么** 系统推送包含币种、方向、价格、止损位的通知

#### 场景:人工确认后下单
- **当** 用户在通知中确认交易
- **那么** 系统通过风控检查后执行真实下单
