## 新增需求

### 需求:归因分析必须支持按信号指标分桶统计
系统必须在归因分析中支持按 signals 表的指标字段分桶，统计每个桶的归因 PNL 和胜率。

#### 场景:按 quality_score 分桶
- **当** 用户执行归因分析指定按 quality_score 分桶
- **那么** 系统将 quality_score 按预定义区间（如 0-3、3-5、5-7、7+）分桶，输出每个桶的笔数、总 PNL、胜率、平均 PNL

#### 场景:按 direction_type 分桶
- **当** 用户执行归因分析指定按 direction_type 分桶
- **那么** 系统输出 main（顺势）和 secondary（逆势）两个桶的笔数、总 PNL、胜率

#### 场景:按 is_counter_trend 分桶
- **当** 用户执行归因分析指定按 is_counter_trend 分桶
- **那么** 系统输出顺势（false）和逆势（true）两个桶的笔数、总 PNL、胜率

#### 场景:按 adx 分桶
- **当** 用户执行归因分析指定按 adx 分桶
- **那么** 系统将 adx 按预定义区间（如 <20、20-30、30+）分桶，输出每个桶的统计

#### 场景:指标值为 NULL 的信号跳过分桶
- **当** 信号的指标字段为 NULL（如 Bollinger 策略的 quality_score）
- **那么** 该信号不计入该指标的分桶统计

### 需求:指标分桶区间必须可配置
系统必须允许用户通过命令行参数指定分桶字段，默认输出所有可分桶指标的统计。

#### 场景:默认输出所有指标分桶
- **当** 用户执行归因分析不指定分桶字段
- **那么** 系统输出 quality_score、direction_type、is_counter_trend、adx 四个维度的分桶统计

#### 场景:指定单个分桶字段
- **当** 用户执行归因分析指定 `--bucket quality_score`
- **那么** 系统仅输出 quality_score 分桶统计
