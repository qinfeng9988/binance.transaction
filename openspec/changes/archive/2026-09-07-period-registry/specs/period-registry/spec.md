## 新增需求

### 需求: 系统必须提供单一来源的交易周期注册表
系统必须在代码中提供一张周期注册表，作为"哪些周期受支持、各自秒数与父级周期"的唯一来源。注册表必须涵盖程序需支持的所有周期，包括 `30m`、`3d`、`1w`，并为每个非终端周期声明父级周期（用于上级趋势确认）；终端周期 `1w` 无父级。

#### 场景: 查询周期的秒数
- **当** 调用 `timeframe_seconds("3d")`
- **那么** 返回 259200

#### 场景: 查询周期的父级周期
- **当** 调用 `parent_timeframe("1d")`
- **那么** 返回 "1w"

#### 场景: 查询终端周期的父级
- **当** 调用 `parent_timeframe("1w")`
- **那么** 返回 None

#### 场景: 查询周期合法性
- **当** 调用 `is_valid_timeframe("1h")`
- **那么** 返回 True
- **当** 调用 `is_valid_timeframe("5mm")`
- **那么** 返回 False

### 需求: 系统必须校验配置中的周期合法性
系统必须在加载策略配置与手动配置时，校验其声明的周期均存在于注册表；任一周期非法时，系统必须拒绝加载并提供明确错误，禁止静默回退。

#### 场景: 策略配置包含未知周期
- **当** `strategies.yaml` 中某策略的 timeframes 含 `"5mm"`
- **那么** 系统输出错误信息并拒绝加载该配置

#### 场景: 手动配置包含未知周期
- **当** `manual_config.yaml` 的查询周期含注册表之外的周期
- **那么** 系统输出错误信息并拒绝使用该周期

### 需求: 量化与手动周期配置必须相互独立
量化策略周期必须在 `strategies.yaml` 中声明，手动查询周期必须在 `manual_config.yaml` 中声明，二者互不引用、互不影响。

#### 场景: 手动查询周期不被量化引擎订阅
- **当** 量化策略未交易某周期（如 `1w`）
- **那么** 该周期不因手动查询需求而被量化引擎订阅

#### 场景: 手动查询清单由手动配置决定
- **当** `manual_config.yaml` 的 `query_timeframes` 声明为 `[15m, 1h, 4h, 1d, 3d, 1w]`
- **那么** 手动查询工具仅接受这些周期，且该清单不写入量化配置
