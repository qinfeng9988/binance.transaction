# 支撑/阻力位多周期趋势确认策略

## 1. 策略概述

| 属性 | 值 |
|------|-----|
| 策略名称 | `support_resistance` |
| 策略类型 | 趋势跟踪 + 技术分析 |
| 核心思想 | 在关键支撑/阻力位附近，结合多周期趋势确认，顺势交易为主、逆势交易为辅 |
| 适用市场 | 高流动性、有明确趋势或区间震荡的加密货币市场 |
| 交易标的 | BTC/USDT, ETH/USDT, SOL/USDT, PAXG/USDT |
| 时间周期 | 5m, 1h, 4h（多周期联动） |

## 2. 核心算法

### 2.1 支撑/阻力位识别

采用三层算法融合识别关键价位：

```
[波段高低点检测] → [价格聚类] → [成交量分布确认]
```

#### 波段高低点检测（Swing High/Low）
- 对于每根 K 线，比较其左右各 N 根 K 线
- 低点低于左右所有低点 → 波段低点（潜在支撑）
- 高点高于左右所有高点 → 波段高点（潜在压力）
- 默认参数：`left=2, right=2`（比较左右各 2 根）

#### 价格聚类
- 将波段高低点按价格聚类（容差 0.5%）
- 同一价格区域出现多次视为强支撑/压力
- 强度 = 触碰次数 + 成交量确认加成

#### 成交量分布确认（Volume Profile）
- 将 K 线数据分成 50 个价格区间
- 统计每个区间的累计成交量
- 高成交量节点附近的支撑/压力位强度 +1

**实现位置：** `quant_trader/technical/support_resistance.py`

### 2.2 趋势判断（双 EMA 交叉）

| 参数 | 值 | 说明 |
|------|-----|------|
| 快线周期 | 21 | EMA(21) |
| 慢线周期 | 50 | EMA(50) |
| 震荡阈值 | 0.3% | 两线间距 < 0.3% 视为震荡 |

**判断逻辑：**
- `EMA(21) > EMA(50)` 且间距 ≥ 0.3% → **上涨趋势 (uptrend)**
- `EMA(21) < EMA(50)` 且间距 ≥ 0.3% → **下跌趋势 (downtrend)**
- 间距 < 0.3% → **震荡 (ranging)**

**实现位置：** `quant_trader/strategies/s_r_levels.py:22-41`

### 2.3 多周期趋势确认

采用「当前周期 + 上级周期」联合判断交易偏向（Bias）：

| 当前周期 | 上级周期 | 交易偏向 (Bias) | 说明 |
|---------|---------|----------------|------|
| 上涨 | 上涨 | `long_only` | 双周期一致上涨，只做多 |
| 下跌 | 下跌 | `short_only` | 双周期一致下跌，只做空 |
| 上涨 | 震荡 | `long_primary` | 上级无明确方向，以当前上涨为主 |
| 下跌 | 震荡 | `short_primary` | 上级无明确方向，以当前下跌为主 |
| 震荡 | 上涨 | `long_primary` | 上级上涨为主，当前震荡允许做多 |
| 震荡 | 下跌 | `short_primary` | 上级下跌为主，当前震荡允许做空 |
| 上涨 | 下跌 | `long_primary` | 上级下跌，做多降为副方向（更严格条件） |
| 下跌 | 上涨 | `short_primary` | 上级上涨，做空降为副方向（更严格条件） |
| 无上级数据 | — | 根据当前趋势回退 | 单周期运行时回退 |

**上级周期映射：**

| 当前周期 | 上级周期 |
|---------|---------|
| 5m | 1h |
| 1h | 4h |
| 4h | 1d |

**实现位置：** `quant_trader/strategies/s_r_levels.py:44-88`

## 3. 交易逻辑

### 3.1 信号生成流程

```
获取 K 线数据
    ↓
多周期趋势确认 → 得到 Bias（交易偏向）
    ↓
识别支撑/压力位
    ↓
根据 Bias 确定各方向的入场条件（主方向/副方向）
    ↓
检查价格与最近支撑/压力位的距离
    ↓
条件满足 → 生成 Signal
```

### 3.2 入场条件

#### 做多（Buy）

| 条件 | 主方向（`long_primary` / `long_only` / `neutral`） | 副方向（`short_primary` 时做多为副方向） |
|------|---------------------------------------------------|----------------------------------------|
| 最少触碰次数 | 2 | 3 |
| 入场距离阈值 | 0.5% | 0.3% |
| 触发条件 | 现价 ≥ 支撑位 且 距离 ≤ 阈值 | 现价 ≥ 支撑位 且 距离 ≤ 阈值（更严格） |

**止损设置：** `stop_loss = 支撑位价格 × (1 - 1.5%)`

#### 做空（Sell）

| 条件 | 主方向（`short_primary` / `short_only` / `neutral`） | 副方向（`long_primary` 时做空为副方向） |
|------|-----------------------------------------------------|----------------------------------------|
| 最少触碰次数 | 2 | 3 |
| 入场距离阈值 | 0.5% | 0.3% |
| 触发条件 | 现价 ≤ 压力位 且 距离 ≤ 阈值 | 现价 ≤ 压力位 且 距离 ≤ 阈值（更严格） |

**止损设置：** `stop_loss = 压力位价格 × (1 + 1.5%)`

### 3.3 出场条件

| 类型 | 条件 | 说明 |
|------|------|------|
| 止损 | 价格触及止损位 | 由策略生成信号时设定，引擎自动监控 |
| 反向信号 | 持有多仓时收到 sell 信号 / 持有空仓时收到 buy 信号 | 先平仓再反向开仓 |
| 同向加仓 | 同方向新信号 | 以新价格加仓，更新持仓均价 |

**实现位置：** `quant_trader/exchange/paper_trading.py`

## 4. 策略参数

```yaml
# quant_trader/config/strategies.yaml 中的参数

params:
  lookback: 100                    # S/R 识别回看 K 线数
  min_touches: 2                   # 主方向最少触碰次数
  stop_loss_pct: 1.5               # 止损距离（%）
  leverage: 5                      # 杠杆倍数（会被风控限制）
  entry_threshold_pct: 0.5         # 主方向入场距离阈值（%）
  secondary_min_touches: 3         # 副方向最少触碰次数
  secondary_entry_threshold_pct: 0.3  # 副方向入场距离阈值（%）
```

| 参数名 | 默认值 | 取值范围 | 调优方向 |
|--------|--------|---------|---------|
| `lookback` | 100 | 50-500 | 增加 → 识别更长期的 S/R，减少噪音 |
| `min_touches` | 2 | 1-5 | 增加 → 更严格的 S/R 确认，信号更少但质量更高 |
| `stop_loss_pct` | 1.5 | 1.0-2.5 | 增加 → 更宽止损，减少假突破，但单笔亏损增大 |
| `leverage` | 5 | 1-5 | 由风控限制，策略设定为期望杠杆 |
| `entry_threshold_pct` | 0.5 | 0.1-1.0 | 增加 → 更早入场，但可能错过最佳位置 |
| `secondary_min_touches` | 3 | 2-5 | 副方向严格程度 |
| `secondary_entry_threshold_pct` | 0.3 | 0.1-0.5 | 副方向入场严格程度 |

## 5. 风控集成

| 风控项 | 策略内实现 | 外部风控接管 | 说明 |
|--------|-----------|-------------|------|
| 止损距离设定 | **是** | 检查 | 策略设定 1.5%，风控检查是否超限 |
| 止损位置计算 | **是** | 否 | 基于 S/R 位计算 |
| 杠杆设定 | 建议值 | **限制** | 策略请求 5x，风控按币种上限调整 |
| 单笔亏损上限 | 否 | **是** | 风控检查 |
| 日累计亏损 | 否 | **是** | 风控检查 |
| 最大持仓数 | 否 | **是** | 风控检查 |
| 信号冷却期 | **是** | 否 | 引擎层 300 秒同币种冷却 |

## 6. 信号模型

```python
Signal(
    strategy_name="support_resistance",
    symbol="BTC/USDT",
    timeframe="5m",
    signal_type="buy",           # "buy" | "sell"
    price=65000.0,               # 当前价格（触发信号时的价格）
    stop_loss=63975.0,           # 止损价格
    leverage=5,
    metadata={
        "support_level": 65000.0,           # 支撑位价格
        "support_strength": 3,              # 支撑强度（触碰次数+成交量加成）
        "distance_to_support_pct": 0.3,     # 现价与支撑位的距离（%）
        "trend": "uptrend",                  # 当前周期趋势
        "parent_trend": "uptrend",           # 上级周期趋势
        "bias": "long_only",                 # 交易偏向
        "is_primary": True,                 # 是否为主方向
    }
)
```

## 7. 执行流程

### 7.1 引擎调度

```
main.py 引擎
    ├── 并发运行 (strategy, symbol, timeframe) 组合
    │     └── 每个组合独立循环：
    │           1. 拉取 K 线 → 存入数据库
    │           2. 获取上级周期 K 线（缓存）
    │           3. 调用 strategy.on_bar()
    │           4. 信号去重（300秒冷却）
    │           5. 风控检查
    │           6. 执行交易（模拟/实盘确认/实盘自动）
    │           7. 休眠至下一周期
    └── 每 10 个周期打印账户概览
```

### 7.2 错开启动机制

为避免多个周期在同一时刻对同一币种发单冲突：
- 各周期首次启动随机延迟 1-5 秒
- 多任务间额外错开 2-8 秒
